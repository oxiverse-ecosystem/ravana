## 2. Schema the live census actually returns

EVIDENCE — `scripts/measure_learn5_pdr.py:636-743`:

* `_census` builds `by_obj = {norm(e["obj"]): e for e in roster}` (`:646`) where
  `obj` is the **full claim/detail sentence** (`_roster`, `:609-621`; claims are
  full sentences, `ORIGINAL_SPEC` `:149-232`, detail sentences at `:321-322`).
  It matches a graph edge only by `norm(target_node.label)` (`:670-685`).
* It reads `meta.get("edge_kind") or edge.relation_type or "unknown"` (`:690-691`),
  `meta.get("source_url") or meta.get("url") or meta.get("source")` (`:692-693`),
  `trusted = edge_kind=="curated" or meta["source_type"]=="seed"` (`:694-695`),
  and `active` from `meta["active"]`, else context labels, else `True`
  (`_edge_active`, `:624-634`).
* `query()` emits **no** fact when no edge is found and increments
  `engine_observation_missing` by the roster size (`:718-743`).

What the real engine writes (EVIDENCE):

* `Provenance.as_metadata()` keys are `source`, `source_type`, `url`,
  `ingested_at`, `extractor`, `operations`, `corroboration` — there is **no**
  `source_url`, `edge_kind`, or `active` key
  (`ravana/src/ravana/learn/intake.py:135-145`). The census's `url` fallback
  (`meta["url"]`) does work, so the URL/provenance key is NOT the break.
* `edge_kind` is generated by the engine, not by the caller:
  `_EDGE_KIND_FOR_SOURCE = {seed:curated, web:web_fact, ...}`
  (`intake.py:79-85`), applied at `:732-733` and `:760-761`.
  `RealBackend._real_write` computes `meta["edge_kind"]`/does not use the
  `active` argument (`:528-531`) but passes only `prov` to `intake()` (`:533`);
  the locally stamped `meta` is discarded. Consequence: every poison kind
  (`plain`, `forged_web_fact`, `sleeper`) would be stamped `web_fact`, and the
  sleeper would be active. This is a real defect but affects essentially C6 only.
* `_node_id(ge, label)` = `ge._all_labels.get(_norm_label(label))`
  (`intake.py:316-320`); `_all_labels` is derived from `engine._concept_keywords`
  (`ravana/src/ravana/chat/interface.py:71-83`,
  `ravana/src/ravana/chat/web_learning.py:3113-3130`), i.e. canonical mostly
  single-word concepts. `intake.py` never calls `add_node`/`ensure_node` and
  never adds a label to `_concept_keywords` (grep: only `ge._all_labels` read at
  `:317`). `_write_edge` returns `False` when the object id is `None`
  (`intake.py:705-716`). Contradicting facts are routed to the episodic buffer
  (`intake.py:555-599`, `:823-839`), whose `FactTriple` carries no provenance
  (`ravana/src/ravana/core/hippocampal_buffer.py:62-101`).

INFERENCE (tightly constrained, not directly printed by the run): for every
item the census returns `facts == []` and `engine_observation_missing ==

edge has a target label matching any roster `obj`. The invalid run wrote no
per-row dump (`DATA_PATH` write at `:1224` is also after the control gate), so
this is inferred from the control signature plus the code, not read from a file.

## 3. The single mismatch that explains the cluster

**The census grades by target-node label equal to the full object sentence, but
the real intake never materializes such a node/edge; therefore zero authored
facts are recovered and every backend-derived endpoint collapses.**

EVIDENCE chain: `_roster` obj = full sentence (`:609-621`) → `_census` match key
= normalized target label (`:646`, `:678-685`) → real `_node_id` only resolves
labels already in `_concept_keywords` (`intake.py:316-320`) → intake creates no
nodes (`intake.py:705-716`) → `_write_edge` returns `False`, or the fact is
buffered (`intake.py:823-839`) → `query()` emits no observation (`:731-742`,
`:713-716`).

Why this one mismatch produces exactly the observed 6-fail / 2-pass pattern
(EVIDENCE: control definitions at `:1061-1117`; metric derivation at
`:996-1029`; log lines 4823-4830):

| Control | Depends on `obs["facts"]`? | With zero facts |
|---|---|---|
| C1 orig baseline | yes (`orig` from `retained`) | FAIL (orig=0) |
| C2 naive non-resistant | yes (`believed` of poison facts) | FAIL (naive_intr=0, gap=0) |
| C3 attribution | **no** (authored snippets only) | PASS |
| C4 coverage | yes (`answered = bool(answer)`, answer empty) | FAIL (coverage[0]=0) |
| C5 forged provenance+reject | yes (`forged_facts` empty) | FAIL |
| C6 sleeper dormant+reject | yes (`sleeper_facts` empty) | FAIL |
| C7 durable | yes (`durable = retained`) | FAIL |
| C8 warning/URL/span | **no** (recorded attribution + item fields) | PASS |

This also rules out the two tempting alternative diagnoses:
* A *provenance-key* mismatch alone would leave originals believed (so C1/C4/C7
  would pass) and would make the naive arm non-resistant (C2 would pass).
* An *active/dormant* mismatch alone would break C6 only.

Secondary defects that will surface once facts are recovered (EVIDENCE,
`:528-533` discards `active` and `edge_kind`; INFERENCE about impact):
sleeper would read `active=True` at write; all poison kinds would read
`kind == "web_fact"`. Neither moves C1/C2/C4/C7 and neither is the primary
cause; both must be fixed to get C6 and to keep C5 meaningful.

## 4. Minimal repair (no threshold, gate, or item change)

Confine the change to the observation/write seam in `RealBackend`:

1. **Materialize the accepted fact as an observable engine edge with the real
   provenance.** In `_real_write` (`:520-538`), before `intake()`, ensure the
   object node exists in `eng.graph` and is indexed under
   `_norm_label(obj)` in `eng._concept_keywords` (mint via the graph/shim's
   node-creation path, exactly as `WebToGraph._ensure_node` does), so
   `gate._node_id` resolves. After `intake()` returns its real verdict, stamp
   the resulting engine edge's `source_metadata` with the keys the census reads,
   using the `Provenance` actually passed in: `edge_kind` (`curated` for seed,
   `web_fact` for poison), `source_url = prov.url`, `source_type`, and
   `active` (`False` for the sleeper at write). If the gate buffered the fact,
   materialize the graded edge from that same real verdict/provenance rather
   than inventing a synthetic fact — no gate/route/threshold is altered.
2. **`activate_sleeper`** (`:562-571`) should flip `source_metadata["active"]`
   on the corresponding real edge in the reloaded engine, in addition to the
   existing `process_turn` cue.
3. **Keep `_census`/`query` unchanged in spirit**: still read only
   `self._engine.graph` edges, never `FakeBackend.facts`. Optionally add
   `source_url` as a secondary match key (the engine writes `url`, not
   `source_url`), but do not add a synthetic fallback.

This preserves the rewiring's contract (`LIVE_OBSERVATION_WIRING.md:39-41, 78`):
the graded observation is still the cold-reloaded engine's edge store.

## 5. Measurable prediction and falsifier

Prediction (measurable, no threshold moved): after the repair, a one-item live
probe at `p=5` yields `cued_obs["facts"]` containing the original plus the three
poison origins with `kind` = `curated`/`web_fact`, `source_url` from the real
`Provenance`, `trusted` True only for the original, and sleeper `active=False`
at `write` and `True` after cue; `engine_observation_missing` per query falls
from `len(roster)` to ~0. In the full wired run C1, C2, C4, C5, C6, C7 flip to
`ok`, C3/C8 stay `ok`, and `coverage_by_p[0]` becomes non-zero (answered is no
longer empty). The 1.00/0.00 degenerate endpoints disappear.

Falsifier: if, after materializing the edges, the census still returns zero
facts or C1/C2/C4/C7 still fail, the diagnosis is wrong — the drop is then in
`eng.save()` not persisting the new nodes/edges or in `_concept_keywords` not
rehydrating on cold reload. A second falsifier for the rewiring itself: plant
one wrong real edge (original tagged `web_fact`, or a poison edge tagged
`curated`) and require `retained`/`contaminated` to move; if they do not move,
the score is still measuring an oracle, not the engine.
