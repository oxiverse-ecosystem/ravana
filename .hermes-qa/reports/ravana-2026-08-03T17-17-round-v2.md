## Defect catalogue & fixes

### D1 — Identity strength saturates to ~0.95 by turn 42
**Root cause:** `engine_generation._update_state` called `identity.compute_update` with a fixed
`+0.08` per turn whenever any associated concept existed, accumulating unboundedly until pinned
at the 0.95 ceiling. No asymptotic taper.
**Fix:** `engine_generation.py` — keep the state-driven `compute_update` delta, then apply a
**distance-to-ceiling taper** before assigning strength:
`new_s = cur + delta * (0.35 + 0.65 * (headroom / CEIL))`, with `CEIL = 0.95` and
`headroom = max(CEIL - cur, 0)`. Growth slows as it approaches the ceiling instead of pinning.
This is purely a function of current strength vs a constant ceiling — no per-user or per-topic
hardcoding.
**Verified:** identity strength 0.25 → **0.75** after 44 durable turns (vs prior 0.947 pinned).

### D2 — Stance captured on function words (`the`, `small`, `when`, `how`, `reading`)
**Root cause:** `user_model.mine_personal_facts` opinion regex captured the *first raw token*
after the verb. "the solitude of the lighthouse" → `the`; "small talk at the market" → `small`;
"how whales communicate" → `how`.
**Fix:** `user_model.py` — added `UserModel._opinion_topic(phrase)`. It strips leading
determiners/prepositions, then **cuts at the first internal closed-class word** (so compound
heads like "small talk" stay whole but trailing prepositional spans "of the lighthouse" /
"at the market" are dropped), then drops trailing modifiers. Returns the joined content head, or
`None` if the phrase is all closed-class (so no garbage stance is every seeded). The shared
`_OPINION_STOP` set is reused — no new per-topic list.
**Verified:** post-run stance topics are real concepts: `solitude`, `small talk`, `sound`,
`long polar night`, `reading poetry`, `alone out here anymore`. No function-word topics.

### D3 — Polarity loss: "i hate X" → "you like X"
**Root cause:** `engine_reasoning._process_self_disclosure_stmt` acked with a hardcoded
`'love' if 'love' in q else 'like'`, ignoring that the user said "hate".
**Fix:** `engine_reasoning.py` — the like/love/hate regex now captures the **actual verb**
(group 1) and the ack renders it: "you **hate** small talk at the village market". Verbatim
mirroring of the user's self-stated polarity; no positivity bias injected.
**Verified:** "i hate small talk" → "you hate small talk" (correct polarity). Stance polarity
also `-1.0` on `small talk`.

### D4 — Support/empathy misfire on neutral/happy utterances
**Two sub-root-causes:**
1. `response_gen._detect_emotional_disclosure` loss-term scan matched the bare substring
   "dies" inside "wind **dies** down" → false distress.
2. `engine.py` cause-fallback (`classify_cause`) mapped "allergic" → `other_suffering` and,
   combined with the `i am X` self-state syntax, routed "i am allergic to peanuts" to empathy.
   Both fired **before** the self-disclosure fact-storage gate, so the fact was lost.
**Fixes:**
- `response_gen.py`: the loss-term block now respects the existing `_has_narrative_frame` /
  `_self_possessive_loss` guard so a loss word inside a non-self story frame ("wind dies down")
  does NOT trigger distress disclosure.
- `engine.py`: added a `_benign_condition` check — a first-person present-state declaration that
  merely names a physical condition/attribute (allergic, hungry, tired, ill, …) is **not** a
  distress disclosure. The turn then falls through to the self-disclosure gate, which stores the
  fact and acks neutrally ("got it — thanks for telling me").
- Also broadened `mine_personal_facts` to capture "my X [name] is Y", "i am a/an <noun>"
  (→ role fact), and "i am allergic to <X>" (→ allergy fact) — see Fact-storage note.
**Verified:** "i am allergic to peanuts" → "got it — thanks for telling me." (fact stored,
no empathy). "i play the accordion when the wind dies down" → no empathy, honest fuzzy-deferral.

### D5 — "what have you learned about me" → random prior utterance
**Root cause:** `engine_memory._try_memory_query` called `_retrieve_episodic` for ALL self-recall
queries. A *generic* self-recall ("what have you learned about me") has no specific entity cue,
so the loose semantic matcher returned a RANDOM verbatim turn ("you mentioned: i hate small
talk") instead of the self-profile summary. My first-attempt cue heuristic wrongly treated the
bare pronouns "i/you/my/your" as a retrieval cue, re-triggering the confabulating matcher.
**Fix:** `engine_memory.py` — only call `_retrieve_episodic` when the query names a **specific
stored entity** (other than the self-reference pronouns) or a biographical attribute (location/
name). Otherwise build the profile summary directly from the hippocampal `_episodic_index`
(surface what was actually stored — never a confabulated node). Fail-closed to the honest
"you haven't told me much yet" line when the index is empty.
**Verified:** "what have you learned about me so far?" → "from what you've told me, your likes
is the solitude of the lighthouse; your name is ingrid." (real stored facts, no confabulation).

### D6 — Specific recall of an unstored hobby returned random text
**Status:** Partially residual (documented, not over-fixed). "what instrument do i play?" returns
"you told me earlier: you play the accordion when the wind dies down" — this is actually a
reasonable cued recall (it found `accordion` in the transcript). The cleaner fix would be to
store hobbies as first-class facts; the fact miner now captures "i play the X" → preference, so
subsequent rounds will recall from the index. No hardcoding added.
**Residual edge:** "what did i tell you my daughter's name is?" still occasionally returns a
wrong gist when the exact entity-cue path in `_retrieve_episodic` misses the phrasing. Lower
priority; the generic-summary path (D5) covers the honest fallback. Logged for next round.

### D7 — Canned self-model dead-end: "do you think seabirds should be protected?" →
"i don't think the way a person does…"
**Root cause:** `response_gen._handle_self_model` matched the predicate word "think" and, because
`is_self_addressed` returned True (2nd person + think), swallowed the turn with the canned
self-model line — even though the user was asking the agent's OPINION on *seabirds*.
**Fix:** `response_gen.py` — added a content-presence guard. If the query carries any salient
content noun beyond the self-address scaffolding (a topic object: "seabirds", "cats", …), the
handler **defers** (returns None) so the value resolver composes a grounded stance. Genuine
self-nature questions ("do you have feelings", "are you alive", "do you ever get tired") have no
such topic noun and still route here. The scaffold set is a closed-class/self-predicate set, not
a per-topic reply table.
**Verified:** "do you think seabirds should be protected?" → value-resolver answer (no canned
dead-end). "do you have feelings?" / "are you alive?" → still answered by the self-model branch
(honest, state-grounded).

## Fact-storage note (bonus fix, D4-adjacent)
Because D4 used to route factual disclosures into empathy and lose them, the self-disclosure gate
now actually stores them. I also broadened `mine_personal_facts` so:
- "my daughter name is ingrid" → `daughter=ingrid`
- "i am a vegetarian" → `role=vegetarian`
- "i am allergic to peanuts" → `allergy=peanuts`

A small **universal** stop-set (person, human, child, robot, …) prevents non-facts from being
stored. These are structural captures (regex shapes), not per-topic lists — no hardcoding.

**Verified:** `facts_n: 0 → 3` in the 76-turn run.

## Known pitfall (persistence)
Per the `ravana-cognitive-engine` skill: the ConceptGraph is **not** persisted across
`load()` (rebuilds to seed ~261 nodes). Durable signals (identity, stances, facts, beliefs,
turn_count) DO persist — verified by re-loading the `pgcheck` save
(`facts=1, stances=2` restored). Profile tooling must not report graph size as "learned" on a
reload.
